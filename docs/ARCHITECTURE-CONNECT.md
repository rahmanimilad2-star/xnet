# مسیر اتصال و نقش 3X-UI

```
3X-UI ──(فقط کانفیگ: inbound/کلاینت یا Subscription URL)──▶ Backend + DB
                                                            │  /api/v1/configs (outbound آماده Xray، از DB)
                                                            ▼
                                                      Android App ──▶ Xray Core (داخل اپ) ──▶ VPN Server
```

## اپ اندروید با چه چیزی حرف می‌زند
| مقصد | کِی | فایل |
|---|---|---|
| Backend خود پروژه: `/api/v1/auth/login`، `/api/v1/account`، `/api/v1/configs`، `/api/v1/events` | ورود، همگام‌سازی دوره‌ای، ثبت رویداد (غیرمسدودکننده) | `data/ApiClient.kt` |
| سرور VPN داخل کانفیگ | هنگام Connect، توسط Xray Core | `vpn/XrayCore.kt`، `vpn/AppVpnService.kt` |
| `https://www.gstatic.com/generate_204` | تست سلامت تونل بعد از اتصال (از داخل خود تونل) | `vpn/XrayCore.kt` |

اپ **هیچ** آدرس، رمز، توکن یا endpoint مربوط به 3X-UI یا Subscription ندارد (بررسی با جستجوی کامل کد).

## Connect دقیقاً چه می‌کند
1. `AppVpnService.connect()` کانفیگ‌ها را از حافظه رمزنگاری‌شده خود اپ برمی‌دارد.
2. اگر حافظه پر است، **بدون منتظر ماندن برای شبکه** Xray Core اجرا می‌شود؛ همگام‌سازی با Backend در پس‌زمینه انجام می‌شود.
   (فقط در اولین اجرا که حافظه خالی است، یک‌بار کانفیگ از Backend گرفته می‌شود.)
3. `VpnService.Builder` تونل TUN می‌سازد، `XrayCore.start(config, tunFd)` هسته را اجرا می‌کند و هسته مستقیم به آدرس/پورت سرور داخل کانفیگ وصل می‌شود.
4. اگر سرور جواب ندهد، کانفیگ بعدی امتحان می‌شود (failover).
5. Disconnect فقط هسته و تونل را می‌بندد؛ یک رویداد «قطع» بدون انتظار به Backend فرستاده می‌شود.

## Backend و 3X-UI
- `/api/v1/*` فقط از دیتابیس محلی جواب می‌دهد و هیچ درخواستی به 3X-UI یا Subscription نمی‌فرستد (تست خودکار دارد).
- ارتباط با 3X-UI فقط در پس‌زمینه یا در عملیات مدیر است: ساخت/تمدید/حذف کلاینت، خواندن مصرف، غیرفعال‌کردن پس از اتمام حجم.
- Subscription URL فقط توسط Backend دریافت می‌شود (ساخت، «به‌روزرسانی» دستی، یا هر `SUBSCRIPTION_REFRESH_MINUTES`).
  لینک‌های بدون تغییر شناسه‌شان حفظ می‌شود تا اپ‌های متصل مجبور به اتصال مجدد نشوند.
- اگر 3X-UI یا Subscription از دسترس خارج شود، کاربران با آخرین کانفیگ‌ها متصل می‌مانند.

## کانفیگ دستی (از هر پنل یا منبع، بدون API)
- پنل ← کانفیگ‌ها ← **«+ افزودن کانفیگ دستی»**: متن را Paste کنید؛ هر خط یکی از `vless://` `vmess://` `trojan://` `ss://` یا لینک Subscription `https://…`.
- «بررسی» برای هر مورد پروتکل، سرور، پورت، نام، UUID/Password (پوشانده‌شده)، Network، Security، SNI، Flow، Method و Path را نشان می‌دهد؛ موارد نامعتبر با پیام خطای دقیق.
- «ذخیره» فقط خود کانفیگ را ذخیره می‌کند (`source = manual`، بدون سرور/رمز/توکن). Subscriptionها جدا ذخیره می‌شوند (`source = subscription`).
- کانفیگ‌های خودکار 3X-UI `source = xui` هستند. همگام‌سازی مصرف فقط روی کلاینت‌های xui (و ایمیل دستی قدیمی) کار می‌کند و هیچ‌وقت سراغ کانفیگ دستی نمی‌رود.
- کاربری که مصرفش جایی اندازه‌گیری نمی‌شود `usage_known=false` می‌گیرد: اپ «حجم نامشخص» نشان می‌دهد و Connect فعال می‌ماند (سقف حجم برای او مسدودکننده نیست؛ تاریخ انقضا و مسدودی همچنان اعمال می‌شود).
